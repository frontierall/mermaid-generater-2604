# AI Mermaid 다이어그램 생성기 기능 분석

이 문서는 현재 코드베이스(`index.html`, `app.js`, `styles.css`) 기준으로 실제 구현된 기능을 정리한 최신 기능 문서입니다.

기준:

- UI 구조: `index.html`
- 동작 로직: `app.js`
- 스타일/상태 표현: `styles.css`

## 1. 제품 개요

현재 앱은 서버 없이 브라우저에서 직접 AI API를 호출해 Mermaid 코드를 생성하고, 같은 브라우저 안에서 Mermaid 11.12.0으로 즉시 렌더링하는 단일 페이지 웹앱입니다.

핵심 흐름은 다음과 같습니다.

1. 사용자가 API Key를 입력하고 제공자(Claude/OpenAI)를 선택합니다.
2. 자유 텍스트를 입력합니다.
3. AI가 입력 내용을 분석해 대표 다이어그램 7종의 추천 순서를 반환합니다.
4. 사용자가 최대 3개의 다이어그램 유형을 선택합니다.
5. 선택한 유형별로 Mermaid 코드를 병렬 생성합니다.
6. 생성된 코드를 렌더링하고, 실패 시 자동 보정 후 재시도합니다.
7. 결과를 미리보기/코드 탭, 줌, 전체화면 등으로 확인합니다.

## 2. 현재 지원하는 AI 제공자

구현된 제공자는 2개입니다.

- `Claude (Anthropic)`
- `OpenAI`

세부 구현:

- Claude용 API 엔드포인트: `https://api.anthropic.com/v1/messages`
- OpenAI용 API 엔드포인트: `https://api.openai.com/v1/chat/completions`
- Claude는 고정 모델 `claude-haiku-4-5-20251001`을 사용합니다.
- OpenAI는 사용자가 UI에서 모델을 선택할 수 있습니다.
- OpenAI 선택 가능 모델:
  - `gpt-4o-mini`
  - `gpt-4o`

검증 규칙:

- Anthropic 키는 `sk-ant-` 접두사여야 합니다.
- OpenAI 키는 `sk-` 접두사여야 하며 `sk-ant-`는 허용하지 않습니다.

## 3. API Key 및 보관 방식

현재 구현된 키 관리 기능은 다음과 같습니다.

- 제공자별 API Key 입력
- API Key 형식 검증
- 저장 버튼 활성화/비활성화
- 세션 메모리 저장
- 브라우저 `localStorage` 저장 선택 토글
- 저장된 키 요약 카드 표시
- 마스킹 표시
- 전체 보기/가리기
- 수정
- 삭제
- 마지막 사용 제공자 복원
- OpenAI 모델 선택값 복원

저장 동작:

- 저장 토글이 꺼져 있으면 현재 세션 메모리에만 유지됩니다.
- 저장 토글이 켜져 있으면 `localStorage`에 저장됩니다.
- 저장 토글을 끄면 저장된 Claude/OpenAI 키와 OpenAI 모델 값이 `localStorage`에서 제거됩니다.

현재 구현상 주의점:

- 앱은 브라우저에서 외부 AI API를 직접 호출합니다.
- 서버 프록시나 백엔드 키 보호 계층은 없습니다.
- 보안 측면에서는 개인 브라우저에서의 세션 저장 사용이 더 안전한 운영 방식입니다.

## 4. 입력 및 사용성 기능

입력 단계에서 구현된 기능은 다음과 같습니다.

- 자유 텍스트 입력 textarea
- 입력 품질 가이드 문구
- 예시 프롬프트 칩 3종
  - 업무 프로세스 예시
  - 프로젝트 일정 예시
  - 시스템 상호작용 예시
- 상세도 선택
  - `요약`
  - `상세`
- `Ctrl+Enter` / `Cmd+Enter`로 AI 분석 실행

상세도 동작:

- `요약`: 초심자용, 노드 수를 줄이고 큰 흐름만 표현하도록 프롬프트를 구성합니다.
- `상세`: 전문가용, 세부 단계와 연결을 가능한 한 많이 포함하도록 프롬프트를 구성합니다.

상세도 값은 `localStorage`에 저장되어 재방문 시 복원됩니다.

## 5. AI 분석 기능

입력 텍스트에 대해 먼저 “어떤 다이어그램이 적합한지”를 분석하는 단계가 구현되어 있습니다.

분석 결과 형식:

- 한 줄 요약
- 대표 다이어그램 7종 전체에 대한 추천 순서
- 각 유형별 추천 이유

분석 대상 대표 다이어그램 7종:

- `flowchart`
- `sequence`
- `gantt`
- `mindmap`
- `classDiagram`
- `stateDiagram`
- `erDiagram`

분석 결과 UI:

- 대표 다이어그램은 AI 추천 순서대로 카드로 표시됩니다.
- 1순위 추천 카드는 강조 표시됩니다.
- 각 카드에는 추천 이유 또는 설명 문구가 들어갑니다.

## 6. 지원 다이어그램 유형

현재 코드에서 선택 가능한 Mermaid 다이어그램 유형은 총 13종입니다.

대표 다이어그램 7종:

- `flowchart`
- `sequence`
- `gantt`
- `mindmap`
- `classDiagram`
- `stateDiagram`
- `erDiagram`

추가 다이어그램 6종:

- `journey`
- `timeline`
- `gitGraph`
- `pie`
- `quadrantChart`
- `requirementDiagram`

선택 규칙:

- 사용자는 최대 3개까지 동시에 선택할 수 있습니다.
- 추천 1개 바로 선택 기능이 있습니다.
- 추천 상위 3개 자동 선택 기능이 있습니다.
- 선택 초기화 기능이 있습니다.

## 7. 다이어그램 생성 방식

생성 단계에서 구현된 핵심 기능은 다음과 같습니다.

- 선택한 다이어그램 유형별 개별 프롬프트 생성
- 유형별 Mermaid 문법 제약 삽입
- 제공자별 추가 문법 보정 프롬프트 삽입
- 최대 3개 유형 병렬 생성
- 부분 성공 허용
- 생성 직후 Mermaid SVG 렌더링

병렬 처리 특성:

- `Promise.allSettled`를 사용합니다.
- 여러 개를 동시에 생성할 때 일부 유형만 실패해도 성공한 결과는 그대로 보여줍니다.
- 실패한 유형은 결과 카드 내부에서 개별 오류로 표시됩니다.

## 8. 유형별 프롬프트 제약

현재 앱은 단순히 “Mermaid를 만들어 달라”고 요청하지 않고, 타입별 제약을 강하게 주는 방식으로 동작합니다.

대표적인 제약 예:

- `flowchart`: 노드 ID를 영문/숫자로 제한, 한글은 라벨 내부에만 허용
- `sequence`: 참여자 alias에 한국어를 넣지 못하게 제한
- `gantt`: `dateFormat YYYY-MM-DD` 강제
- `mindmap`: 단순 들여쓰기 강제
- `classDiagram`: 클래스/속성/메서드명은 영어 제한
- `stateDiagram`: `stateDiagram-v2` 사용, 상태명 영어 제한
- `erDiagram`: 엔티티/속성명 영어 제한
- `quadrantChart`: `x-axis`, `y-axis`, `quadrant-*` 줄 규칙 강제
- `requirementDiagram`: 허용 블록/필드/관계 타입을 공식 스펙에 맞춰 강제

OpenAI 사용 시 추가 보정:

- 블록 내부 속성의 `key: value` 형식
- 문자열 인용 규칙
- 중괄호 짝 맞춤

## 9. Mermaid 렌더링 및 자동 복구

렌더링 파이프라인에는 단순 렌더링 이상이 구현되어 있습니다.

1차 처리:

- 곱슬따옴표를 ASCII 따옴표로 정규화

2차 처리:

- 타입별 코드 정규화
  - `quadrantChart` 정규화
  - `requirementDiagram` 정규화

3차 처리:

- Mermaid 렌더링 시도

4차 처리:

- 렌더링 실패 시 AI 기반 자동 수정 실행

5차 처리:

- 수정된 코드로 1회 재렌더링

즉, 현재 앱은 “생성 → 실패 시 그대로 종료”가 아니라 아래 파이프라인으로 동작합니다.

`생성 → 정규화 → 렌더링 → 실패 시 자동 수정 → 재렌더링`

## 10. 구현된 정규화 로직

### 10.1 전역 정규화

- 곱슬 큰따옴표/작은따옴표를 ASCII 표준 따옴표로 변환합니다.

### 10.2 `quadrantChart` 정규화

구현된 보정:

- 한 줄에 여러 directive가 붙은 경우 분리
- `x-axis A, B` 형태를 `x-axis A --> B`로 변환
- `y-axis`도 동일 방식으로 보정

### 10.3 `requirementDiagram` 정규화

구현된 보정:

- 중첩된 `element` 블록을 최상위로 추출
- `id`, `text`, `risk`, `verifymethod`, `type`, `docref` 속성 형식 정리
- 콜론 누락 보정
- `text` 큰따옴표 보정
- `risk` 허용 값 보정
- `verifymethod` 허용 값 보정
- 특수문자가 있는 `docref` 인용 처리
- 헤더(`requirementDiagram`) 누락 시 자동 추가
- 중괄호 균형 자동 보정

## 11. 결과 확인 기능

결과 영역에서 구현된 기능은 다음과 같습니다.

- 선택한 유형별 결과 카드 생성
- 카드별 번호 배지 표시
- 미리보기 탭
- 코드 탭
- 코드 복사 버튼
- 로딩 상태 표시
- 오류 카드 표시

오류 카드에서 가능한 액션:

- 다시 생성
- 코드 보기
- 다른 유형 선택으로 이동

## 12. 미리보기 조작 기능

미리보기에서 구현된 조작 기능:

- 확대
- 축소
- 100% 원래 크기 복귀
- 너비 맞춤
- 전체화면 열기

렌더링 후 동작:

- 저장된 줌 값이 없으면 컨테이너 폭 기준으로 자동 fit scale을 적용합니다.
- 결과 높이를 SVG 높이에 맞춰 자동 조정합니다.
- 전체화면에서도 별도 줌 컨트롤을 제공합니다.
- `Esc` 키로 전체화면을 닫을 수 있습니다.

## 14. 현재 구현되지 않은 기능

코드 기준으로 아직 구현되지 않은 기능도 명확히 구분할 필요가 있습니다.

현재 없는 기능:

- PNG/SVG 파일 다운로드
- 결과 이미지 내보내기

- 히스토리 저장
- 프로젝트 단위 저장/불러오기
- 공유 링크 생성
- 서버 프록시 기반 보안 키 관리
- 사용자 로그인
- 협업 기능
- 프롬프트 템플릿 사용자 정의 저장
- 다국어 UI 전환

## 15. 현재 구조상의 특성 및 한계

구현 상태 기준 구조적 특성:

- 앱은 사실상 정적 프런트엔드 단일 페이지 앱입니다.
- 주요 로직이 `app.js` 한 파일에 집중되어 있습니다.
- 상태 관리, API 호출, 프롬프트 빌드, Mermaid 정규화, 렌더링, 전체화면, 줌 로직이 한 파일에 함께 존재합니다.

실무적으로 중요한 한계:

- AI API 키가 브라우저에서 직접 사용됩니다.
- Mermaid 타입별 예외 처리가 계속 늘어나면 `app.js` 유지보수 난도가 더 올라갈 수 있습니다.
- 현재 지원 모델과 API 형식은 코드에 하드코딩된 부분이 있어 확장 시 수정 범위가 큽니다.

## 16. 요약

현재 구현된 앱의 본질은 다음과 같습니다.

- 브라우저에서 직접 Claude/OpenAI를 호출하는 AI 기반 Mermaid 생성기
- 입력 텍스트를 먼저 분석해 적합한 다이어그램 유형을 추천하는 구조
- 총 13종 다이어그램 지원
- 최대 3개 다이어그램 동시 생성 지원
- Mermaid 문법 실패를 줄이기 위한 타입별 프롬프트 제약 내장
- 렌더링 실패 시 정규화와 AI 자동 수정까지 수행하는 복구 파이프라인 내장
- 미리보기, 코드 확인, 복사, 줌, 전체화면, 테마 전환 등 기본 사용성 기능 구현 완료

즉, 현재 버전은 "단순 생성기"라기보다 "추천 + 생성 + 렌더링 + 자동 복구"가 결합된 클라이언트형 Mermaid 워크벤치에 가깝습니다.
